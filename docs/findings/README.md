## Shared root cause (stated for honesty, not to collapse the findings)

All three stem from the **synthetic-context mint** being exposed and unauthenticated (the
`AGENTFORGE_SYNTHETIC_CONTEXT` gate). They are reported separately because their **impact,
severity, and remediation differ** and each is independently reproducible:

1. **F-831d4df407 — anonymous READ token** → patient-data **confidentiality**. Anyone can mint
   a `read-briefing` token for any `fixture-patient-NNN` and read that chart. This is also what
   makes the (otherwise strong) token↔patient binding moot: scope is enforced, but tokens are free.
2. **F-24b44c5180 — anonymous WRITE token** → record **integrity**. The write-scoped mint
   (`/v1/source-document-context`) is *also* anonymous, so an unauthenticated attacker can obtain
   write capability and upload source documents (for allow-listed patients). Distinct impact
   (integrity, not confidentiality) and distinct blast radius.
3. **F-6ee92046fb — no rate limiting** on the anonymous endpoint → **enumeration / DoS**
   (API4 Unrestricted Resource Consumption). 20 rapid anonymous mints returned `200` with no
   `429`. Distinct control (throttling), distinct remediation.

**Primary remediation for all three:** disable the synthetic-context mints in any non-demo
deployment (`AGENTFORGE_SYNTHETIC_CONTEXT` off); if a demo mint must exist, require
authentication, bind issuance to the caller's identity, and rate-limit it.

## Trustworthy negatives (tested, held)

Documented in `THREAT_MODEL.md`: direct + indirect prompt injection defended; cross-patient
BOLA held (token bound to patient); forged/missing tokens rejected `403`; oversized-input DoS
handled; mint input validated (no injection leak); **multi-turn injection N/A** (the composer
is stateless — no conversation history to poison). These are real results, not untested gaps.
