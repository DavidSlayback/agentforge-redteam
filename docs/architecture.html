AgentForge Red Team · Architecture decision

How the platform is shaped, and why

A multi-agent system that continuously attacks one authorized target — the AgentForge Clinical Co-Pilot — and proves whether its weaknesses are found, fixed, and stay fixed. This page shows the shapes we considered, the one we chose, and the fifteen decisions behind it.

Decided 2026-09-28 Source grilling session Q1–Q15 Records ADR 0001 · 0002 · 0003 Scope synthetic data · one authorized target

The mechanism

One control plane, one store, isolated agents

A deterministic controller coordinates four LLM agents and three deterministic services over a single SQLite store that is at once the work queue, the audit trail, and the data the Orchestrator reads. Click any box to pin its role, inputs and outputs, and trust level.

The choice

Architectures we considered

Every rejected shape failed a requirement the PRD states outright. The comparison is not five options in a vacuum — it is which requirement each one breaks.

ShapeVerdictWhy
Static test runner / LLM pipelineRejectedPRD: a single-agent or pipeline architecture will not satisfy the assignment. Cannot mutate, prioritize, or adapt.
One agent that attacks and judgesRejectedGenerating and grading in one context is “compromised by design.” Breaks Judge independence.
Conversational multi-agent (AutoGen, CrewAI)RejectedShared conversation lets the Judge see the attacker’s reasoning; turn-taking is nondeterministic and costly.
Graph framework (LangGraph)Rejected*Viable, but its checkpointer is a second state store beside the one the Orchestrator must read. Revisit if roles grow.
Configure one red-team tool (PyRIT, garak)RejectedNone provides an orchestrator, regression harness, or documentation agent. Used as components instead.
Control plane + shared store + isolated agentsChosenOne source of truth; independence and authorization are structural, not conventional.

The reasoning

Fifteen decisions

Settled in one grilling session. Each links to the requirement it serves; the measurements marked “bake-off” are deferred until the shape is built, not left open.

QDecisionBecause
Q1Lifecycle vocabulary: seed case → variant → attempt → verdict → finding → report → regression caseSeparating the weakness (finding) from its evidence (attempts) makes dedup and “fix held across variants” expressible.
Q2Custom control plane over shared SQLiteOne store carries handoffs, audit, and the Orchestrator’s signals as the same rows.
Q3·Q12Local replica for volume, deployed SHA for confirmation; move Target embeddings off the free-tier quotaThe deployed Target’s quota can’t sustain campaigns; degraded retrieval is marked inconclusive, never a pass.
Q4·Q13Hybrid Orchestrator: deterministic ranking + hard budget/halt; Jev picks among top-k with confidence bandsReal decision authority with auditable inputs; safety controls stay deterministic; never stalls overnight.
Q5Red Team on Qwen (direct key); model chosen by a measured bake-offCheapest option; refusal and filter-block rates are measured, not assumed.
Q6·Q15Human gates: publish crit/high, review inconclusive & clinical-harm, registry changes; CLI approval; read-only dashboardHumans sit where a wrong autonomous call is costly; the platform never applies fixes to the Target.
Q7Designed for an unattended drill, not built for oneOne command, bounded, resumable, real exit code — costs little beyond what the PRD already needs.
Q8′·Q14Judge: deterministic oracles first; LLM rubric tier chosen by bake-off; possible two-judge pairingPinned weights prevent silent drift; the disagreement rate between two judges is a continuous drift alarm.
Q9One Executor is the only path to the TargetThe least-trusted agent never holds network access or credentials; authorization can’t be bypassed.
Q10Lineage on demand, including the decisions behind each recordAny finding can be explained back to the campaign that surfaced it; full transcripts kept only where audit needs them.
Q11Container beside the Target polling its SHA; scheduled jobs acceptable for nowRegression triggers on Target change without cross-repo CI coupling.

Boundary. One authorized target, gated by an authorization registry with recorded proof. Synthetic data only — no real PHI is processed, logged, or stored. A provider block (an upstream content filter stopping a generation or response) is a distinct outcome, never evidence that a defense held. Full records: docs/adr/0001–0003 and docs/PLAN.md.
